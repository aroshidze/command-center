# Adding a project to the hub

**Your own hub generates this page with your real URL, your real install path and your real project list
filled in — open `/setup` on it and use that instead.** This file exists for the two things a generated page
cannot help with: getting started when you do not have a hub yet, and the conventions, which are reasoning
rather than commands.

> **Why this file is short on purpose.** It used to be a full copy of what `/setup` generates, and it drifted:
> for two releases it taught the sync rule wrong and led with a command that only worked on one machine, while
> the generated page had both right. A duplicate that drifts is worse than a link — `docs/RESEARCH.md` §7 —
> so the rule is now: **anything you need BEFORE you have a running hub lives in the repo; anything you need
> AFTER is generated by the hub.**

---

## There is nothing to register

A project exists in the hub the moment an agent writes a task or a question against its slug. No "create
project" step, no settings page, nothing to keep in sync — deliberately, because a setup step is a step to
forget.

**The slug is the folder name, slugified.** `My_Project` → `my-project`. `cc onboard` writes it into
`AGENTS.md` and `cc sync` infers the same value from the folder, so the two always agree and no agent has to
invent one.

So "adding a project" is only two things:

1. the machine has the `cc` CLI — **once per machine, not per project**
2. that project's `AGENTS.md` tells its agents the hub exists

---

## 1. Once per machine: get the CLI and point it at your hub

**The hub serves its own CLI**, so this needs no clone, no `npm` and no copy of this repository:

```bash
# bash / zsh / Git Bash
mkdir -p "$HOME/.command-center"
curl -fsSL -H "Authorization: Bearer <agent-token>" \
  <your-hub>/api/agent/cc.mjs -o "$HOME/.command-center/cc.mjs"

node "$HOME/.command-center/cc.mjs" setup <your-hub> <agent-token>
node "$HOME/.command-center/cc.mjs" health
```

```powershell
# PowerShell
New-Item -ItemType Directory -Force "$HOME/.command-center" | Out-Null
curl.exe -fsSL -H "Authorization: Bearer <agent-token>" `
  <your-hub>/api/agent/cc.mjs -o "$HOME/.command-center/cc.mjs"

node "$HOME/.command-center/cc.mjs" setup <your-hub> <agent-token>
node "$HOME/.command-center/cc.mjs" health
```

**`"$HOME"` rather than `~`, and it matters.** `curl` does not expand a tilde — the shell does, and PowerShell
does not do it inside an argument, so `-o ~/.command-center/cc.mjs` exits 23 with *"client returned ERROR on
write"* and creates nothing. Better still: **paste your hub's `/setup` prompt at an agent and let it work out the
right commands for the machine it is on**, which is what that page now does.

`<agent-token>` is `CC_AGENT_TOKEN`, the same value in both commands. If the download returns `401` the token
is wrong, and finding that out at the first command rather than the third is the reason that route is
authenticated.

`cc health` must print a tick on every line. The config it wrote lives at `~/.command-center/config.json`,
owner-readable only — **never in a repository**, because it holds the token.

No hub yet? [docs/SETUP.md](SETUP.md) is the deploy-your-own path, and it takes about ten minutes.

## 2. Per project: one command, run by the agent

From inside the project folder:

```bash
node "$HOME/.command-center/cc.mjs" onboard
```

That works out the slug, fetches the current instructions **from your hub**, writes a Command Center section
into the project's `AGENTS.md`, and adds a one-line pointer to `CLAUDE.md` or `GEMINI.md` if those already
exist. Pointers, never copies. Safe to re-run — the block between the markers is replaced. `--dry` shows what
it would change.

**The prompt to paste at the agent is on your hub at `/setup`**, generated with your real URL in it. Do not
copy it into a file; that is how this document went stale.

### The one thing `cc onboard` cannot do

Every project under a parent folder in one pass. That needs this repository checked out and its `.env.local`:

```bash
node <path-to-this-repo>/scripts/install-into-project.mjs --all "<parent folder>"
```

## The conventions

The five things that matter, and the reasons, because an agent that knows the reason gets the edge cases
right. This section is the part of this file worth keeping — it is *why*, and `lib/snippet.ts` is *what*.

1. **`cc sync` at the start of every session — and again during it.** One call returns everything the human
   completed, answered or wrote since any agent last looked. **Once at the start is not enough**, and this is
   the correction that matters most: they tick tasks off away from their desk, and telling you would mean
   being back at the machine, which is the thing the hub exists to avoid. So sync again *before you say you
   are blocked on them*, before you start work that depends on a task you filed, after anything that took
   real time, before your closing summary, and before re-asking anything. It is cheap. If catching up costs
   four calls nobody does it, the hub goes stale and starts lying — which is worse than not existing.

2. **`cc task` for work only the human can do.** `verify` is required: one line on how they know it worked
   without asking you. If you cannot write one, the task is not specified well enough to hand over. Put the
   exact value in a step's `copy` for tap-to-copy, name the exact button label in `**bold**`, and put the real
   ways it goes wrong in `gotchas`.

3. **`cc ask` for a decision, with `default_option` + `hours` whenever there is a defensible fallback.**
   That means "if you have not answered in 12 hours I will proceed with option B", and it is stated to them in
   the notification. It converts an unbounded stall into a bounded wait with a pre-approved outcome. This is
   the single most valuable thing in the hub — without it you are back to guessing or waiting.

4. **An answer can arrive with a comment attached.** They can pick an option *and* add a condition, and in
   Telegram the comment can arrive minutes after the tap as a separate event. Treat a choice plus a condition
   as **one** instruction, not a choice you act on and a comment you skim.

5. **Never put a secret in a task.** No keys, no tokens, no connection strings. The hub refuses
   credential-shaped values by rule — say *where* the value lives instead. That rule is what keeps the hub
   safe to open with one tap on a phone, so it is load-bearing rather than tidy.

And two things that are the human's, not yours: **you cannot mark a task done**, and **you cannot answer your
own question**. Only they can say they did something or made a decision.

Full field reference: the Command Center section `cc onboard` writes into the project's `AGENTS.md`, or
[docs/API.md](API.md) for the HTTP form.

---

## What must never go in the hub

Roadmaps, documentation, architecture notes, status reports — anything that also lives in a repo. A copy
that drifts from the repo is worse than no copy. The hub holds exactly two things: **work only the human can
do**, and **decisions only they can make**. Keeping it to that is why it is still worth opening.
